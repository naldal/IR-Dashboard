# IR Dashboard

위메이드 IR실이 **주가·시가총액·지수·환율·투자자 동향**을 한 화면에서 빠르게 확인할 수 있도록 만든 웹 대시보드입니다.

## 30초 요약

이 프로젝트는 크게 **3층 구조**로 되어 있습니다.

1. **화면 층**: 브라우저에 보이는 카드와 차트를 그립니다.
2. **정리 층**: 화면이 바로 외부 증권 API를 호출하지 않고, 프로젝트 안의 서버 API가 중간에서 데이터를 정리합니다.
3. **데이터 공급 층**: 한국투자증권(KIS) API와 Yahoo Finance에서 실제 숫자를 가져옵니다.

즉, 이 프로젝트는 **“외부에서 숫자를 받아 → 우리 형식으로 정리하고 → 보기 쉬운 화면으로 보여주는 웹 서비스”**입니다.

---

## 이 프로젝트를 한 장으로 이해하기

```text
사용자 브라우저
   ↓
app/page.tsx (메인 화면)
   ↓
hooks/useStockData.ts (데이터 요청/주기적 새로고침)
   ↓
app/api/stock/* (프로젝트 내부 서버 API)
   ↓
lib/kisToken.ts (KIS 인증 토큰 관리)
   ↓
외부 데이터 제공처
- 한국투자증권 KIS Open API
- Yahoo Finance (원/달러 환율)
```

### 비유로 설명하면
- `app/page.tsx` = **전광판**
- `hooks/useStockData.ts` = **전광판에 올릴 숫자를 계속 확인하는 비서**
- `app/api/stock/*` = **각 부서에서 숫자를 받아 종합하는 상황실**
- `lib/kisToken.ts` = **외부 시스템 출입증(토큰) 관리실**

## 폴더 구조와 역할

```text

│     ├─ exchange/route.ts    # 원/달러 환율
│     ├─ price/route.ts       # 위메이드 주가
│     ├─ index/route.ts       # KOSPI / KOSDAQ
│     ├─ investor/route.ts    # 투자자별 순매매
│     ├─ sector/route.ts      # 게임 섹터 종목 등락률

│  └─ routeError.ts           # API 에러 응답 공통 처리
├─ public/                    # 정적 파일
├─ package.json               # 실행 스크립트 / 라이브러리 목록
└─ README.md
```

## 중요한 파일을 쉽게 설명하면

| 파일 | 역할 | 쉽게 설명하면 |
| --- | --- | --- |
| `app/page.tsx` | 메인 화면 | 사용자가 실제로 보는 대시보드 화면입니다. 카드, 차트, 다크모드 UI가 여기 있습니다. |
| `hooks/useStockData.ts` | 데이터 흐름 제어 | “지금 어떤 숫자를 화면에 보여줄지”를 관리합니다. 처음 로딩, 주기적 새로고침, 장중 여부 판단도 여기서 합니다. |
| `app/api/stock/dashboard/route.ts` | 핵심 종합 API | 여러 외부 데이터를 한 번에 모아 화면이 쓰기 쉬운 형태로 돌려주는 중심 역할입니다. |
| `app/api/stock/*.ts` | 개별 API | 주가, 지수, 환율, 투자자 데이터처럼 기능별로 나뉜 작은 창구들입니다. |
| `lib/kisToken.ts` | 인증/보안 | KIS API를 쓰려면 토큰이 필요한데, 이 파일이 토큰을 발급받고 저장하고 만료 시 재발급합니다. |
| `lib/routeError.ts` | 예외 처리 | API 오류가 났을 때 같은 형식으로 에러를 반환하도록 맞춰줍니다. |

## 데이터가 실제로 움직이는 순서

### 1) 사용자가 페이지를 열면
- `app/page.tsx`가 화면을 띄웁니다.
- 동시에 `useStockData()` 훅이 실행됩니다.

### 2) 훅이 내부 API를 호출합니다
- `/api/stock/dashboard` : 주가 + 지수 + 투자자 동향 + 섹터 + 차트 데이터
- `/api/stock/exchange` : 원/달러 환율

### 3) 내부 API가 외부 데이터를 가져옵니다
- 국내 주식/지수/투자자 데이터는 **KIS Open API**에서 조회합니다.
- 환율은 **Yahoo Finance**에서 가져옵니다.

### 4) 서버가 데이터를 정리합니다
- 외부 API 응답은 그대로 쓰기 어렵기 때문에,
- 내부 API가 화면에서 쓰기 좋은 JSON 형태로 가공해서 반환합니다.

### 5) 화면이 다시 그려집니다
- `useStockData.ts`가 받은 데이터를 state에 저장합니다.
- `app/page.tsx`는 그 state를 읽어서 카드와 차트를 갱신합니다.

---

## 왜 `/api`가 중간에 한 번 더 필요한가?

이 프로젝트를 설명할 때 가장 중요한 포인트 중 하나입니다.

브라우저가 KIS API를 직접 호출하지 않고, **프로젝트 내부의 `/api/...`를 거치는 이유**는 아래와 같습니다.

1. **보안**: KIS 앱키/시크릿을 브라우저에 노출하면 안 됩니다.
2. **정리**: 외부 데이터 형식이 제각각이어서, 화면에서 바로 쓰기 불편합니다.
3. **재사용**: 여러 화면이 생겨도 같은 내부 API를 공통으로 쓸 수 있습니다.
4. **장애 대응**: 토큰 만료, 응답 오류, 재시도 같은 처리를 한 곳에서 관리할 수 있습니다.

즉, `/api`는 단순한 우회가 아니라 **보안 + 정리 + 안정성**을 위한 중간 계층입니다.

## 자동 새로고침 구조

`hooks/useStockData.ts` 기준으로 현재 동작은 다음과 같습니다.

- **처음 진입 시**: 전체 데이터 1회 로드
- **장중일 때 10초마다**: 빠른 요약 데이터 재조회
  - 위메이드 주가
  - 시가총액
  - KOSPI / KOSDAQ
  - 환율
- **5분마다**: 전체 데이터 백그라운드 갱신
- **1분마다**: 한국 증시 장중 여부 재판단

이 구조는 “자주 바뀌는 숫자는 자주 갱신하고, 무거운 데이터는 조금 덜 자주 갱신”하려는 설계입니다.

---

## 현재 화면 기준으로 보면

### 실시간에 가까운 데이터
상단 카드 5개는 `useStockData.ts`를 통해 실제 API 데이터를 받아 표시합니다.

- 위메이드 주가
- 시가총액
- KOSPI
- KOSDAQ
- 원/달러 환율

### 정적(하드코딩) 데이터
하단 4개 비교 차트는 현재 `app/page.tsx` 안의 상수 데이터로 그려지고 있습니다.

- 위메이드 투자자별 순매매 동향
- 게임 TOP10 지수 vs 국내 증시
- 주요 게임업종 누적 등락률
- KOSDAQ 업종 비교

즉, **데이터를 받아오는 기반은 이미 준비되어 있지만, 하단 차트는 아직 샘플/고정 데이터 중심으로 연결되어 있는 상태**입니다.

참고로 `useStockData.ts` 안에는 이미 아래 상태가 준비되어 있습니다.

- `chartHistory`
- `sectorData`
- `investorData`

따라서 추후에는 이 값을 하단 차트에 연결해 **완전한 실시간 대시보드**로 확장하기 쉬운 구조입니다.

## AI를 활용해 이 프로젝트를 다시 만드는 플로우

이 프로젝트와 비슷한 결과물을 다시 만들고 싶다면, 가장 쉬운 방법은 **한 번에 전부 만들려고 하지 말고, AI에게 역할별로 나눠서 요청하는 것**입니다. 현재 코드 구조를 기준으로 하면 아래 순서가 가장 자연스럽습니다.

### 1) 먼저 AI에게 완성 목표를 짧게 정의합니다
처음부터 세부 구현을 묻기보다, 어떤 화면과 어떤 데이터를 보여줄지 먼저 고정하는 것이 좋습니다.

예시 요청:

```text
Next.js로 IR용 증시 대시보드를 만들고 싶어.
상단에는 위메이드 주가, 시가총액, KOSPI, KOSDAQ, 원/달러 환율 카드를 보여주고,
하단에는 게임업종 비교 차트를 배치해줘.
외부 API는 직접 브라우저에서 부르지 말고 내부 API를 두는 구조로 설계해줘.
```

### 2) AI에게 기본 뼈대를 먼저 만들게 합니다
이 프로젝트의 기본 뼈대는 **Next.js 앱 1개**입니다.
AI에게 아래와 같이 요청하면 전체 골격을 빠르게 잡을 수 있습니다.

- Next.js + TypeScript 프로젝트 생성
- `app` 라우터 사용
- Tailwind CSS 설정
- 대시보드 메인 페이지 생성
- `app/api` 아래에 서버 API 라우트 폴더 생성

즉, 첫 단계에서는 “작동하는 빈 골격”을 만드는 것이 목표입니다.

### 3) 화면과 데이터 흐름을 분리하게 합니다
이 프로젝트는 화면 파일 하나에서 모든 것을 처리하지 않고, 아래처럼 나눠져 있습니다.

- `app/page.tsx` : 화면
- `hooks/useStockData.ts` : 데이터 요청과 새로고침
- `app/api/stock/*` : 서버 API
- `lib/kisToken.ts` : 인증 토큰 관리

AI에게도 이 구조대로 나누어 달라고 요청하면, 나중에 수정할 때 훨씬 편합니다.

예시 요청:

```text
화면 컴포넌트와 데이터 요청 로직을 분리해줘.
메인 화면은 app/page.tsx에 두고, 데이터 polling과 상태 관리는 hooks/useStockData.ts로 분리해줘.
```

### 4) 외부 API를 직접 붙이지 말고, 내부 API부터 만들게 합니다
이 프로젝트에서 중요한 설계 포인트는 **브라우저 → 내부 API → 외부 API** 흐름입니다.
AI에게도 바로 주가 API를 화면에 붙이라고 하기보다, 먼저 아래 API를 만들게 하는 편이 좋습니다.

- `/api/stock/price`
- `/api/stock/index`
- `/api/stock/exchange`
- `/api/stock/investor`
- `/api/stock/sector`
- `/api/stock/chart`
- `/api/stock/dashboard`

이렇게 하면 화면은 내부 API만 바라보면 되고, 외부 서비스가 바뀌어도 수정 범위가 줄어듭니다.

### 5) 인증이 필요한 외부 API는 별도 파일로 관리하게 합니다
현재 프로젝트는 KIS Open API를 쓰기 때문에 앱키, 시크릿, 액세스 토큰 관리가 필요합니다.
이 부분을 화면 코드에 섞지 않고 `lib/kisToken.ts`로 분리한 것이 핵심입니다.

AI에게 요청할 때도 아래처럼 분리 요구를 명확히 하는 것이 좋습니다.

```text
KIS API 인증 토큰 발급, 캐시, 만료 시 재발급 로직을 lib/kisToken.ts로 분리해줘.
다른 API route에서는 fetchKisApi 같은 공통 함수만 사용하게 해줘.
```

### 6) 처음에는 카드부터, 그다음 차트 순서로 만들게 합니다
한 번에 모든 차트를 붙이려 하면 디버깅이 어려워집니다. 이 프로젝트를 다시 만든다면 아래 순서가 안정적입니다.

1. 상단 요약 카드 5개부터 완성
2. 환율/지수/주가 숫자 갱신 확인
3. 장중 여부 배지 추가
4. 다크모드 추가
5. 하단 차트 1개씩 연결
6. 마지막에 애니메이션과 로딩 상태 추가

즉, **요약 정보 → 데이터 연결 → 시각화 확장** 순서가 좋습니다.

### 7) 처음 차트는 샘플 데이터로 그리고, 나중에 실데이터로 교체합니다
현재 코드도 하단 차트는 정적 데이터로 먼저 구성되어 있습니다. 이 방식은 AI와 작업할 때 특히 유리합니다.

추천 흐름:

1. 먼저 Recharts로 카드/차트 레이아웃 완성
2. 샘플 데이터로 색상, 범례, 축, 반응형 동작 확인
3. 이후 `chartHistory`, `sectorData`, `investorData`와 연결

이렇게 하면 “화면 문제”와 “데이터 문제”를 분리해서 고칠 수 있습니다.

### 8) 새로고침 주기까지 AI에게 구체적으로 지정합니다
이 프로젝트는 단순 조회가 아니라, 장중에 숫자가 계속 갱신되는 대시보드입니다. 그래서 polling 규칙까지 같이 요청해야 결과가 비슷해집니다.

현재 구조를 재현하려면 AI에게 아래 조건을 주면 됩니다.

- 최초 진입 시 전체 데이터 로드
- 장중에는 10초마다 빠른 요약 데이터 갱신
- 5분마다 전체 데이터 갱신
- 1분마다 장중 여부 재판단

이 조건이 빠지면 단순 정적 페이지가 되기 쉽습니다.

### 9) 마지막에는 “구조 설명 문서”도 같이 만들게 합니다
실제로 프로젝트를 다시 만들 때는 코드만 만드는 것보다, README까지 같이 정리해 두는 것이 훨씬 중요합니다.
특히 AI에게 아래 항목까지 문서화하게 하면 인수인계가 쉬워집니다.

- 폴더 구조
- 데이터 흐름
- 환경 변수
- 외부 API 목록
- 자동 새로고침 규칙
- 아직 샘플 데이터인 부분

### 10) 추천 작업 순서 요약

```text
1. 목표 정의
2. Next.js 기본 프로젝트 생성
3. 화면 / 훅 / 내부 API / 인증 유틸로 구조 분리
4. KIS / 환율 API 연결
5. 상단 카드 완성
6. 자동 새로고침 추가
7. 하단 차트 샘플 데이터로 구현
8. 하단 차트를 실데이터와 연결
9. README로 구조 문서화
10. 배포 후 운영
```

이 순서대로 AI와 작업하면, 현재 저장소와 매우 비슷한 구조를 비교적 안정적으로 다시 만들 수 있습니다.

## 환경 변수 (외부 API 연결용)

로컬 실행 또는 배포 시 아래 값이 필요합니다.

```bash
KIS_APP_KEY=...
KIS_APP_SECRET=...
KIS_BASE_URL=...
```

일반적으로 `.env.local` 파일에 넣어 사용합니다.

```bash
KIS_APP_KEY=your_app_key
KIS_APP_SECRET=your_app_secret
KIS_BASE_URL=https://openapi.koreainvestment.com:9443
```

## 로컬에서 실행하는 방법

이 저장소는 `package-lock.json`이 있으므로 **npm 기준**으로 실행하는 것이 가장 자연스럽습니다.

```bash
npm install
npm run dev
```

브라우저에서 아래 주소를 열면 됩니다.

```text
http://localhost:3000
```
